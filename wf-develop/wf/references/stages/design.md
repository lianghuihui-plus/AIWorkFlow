# 技术设计

## 目标

结合已批准需求和当前代码仓库，形成模块、文件、类、职责、接口与关键交互方案。

## 工作方式

- 先阅读当前代码，复用现有架构和工程惯例。
- `anchored` 设计使用真实文件与符号作为代码证据；空仓库才使用 `greenfield`。
- 设计覆盖当前已接受需求，但不拆分执行任务，也不设计单元测试。
- 不处理 Git 状态、文件归属或下游影响分类。

## 最低交付

Markdown 应说明现状、方案、模块职责、关键流程、接口、风险与验证方向。结构化结果记录覆盖的需求和代码证据。

## 必须停止

关键业务行为或架构约束缺失，并且不同答案会显著改变实现方案时停止并提问。
