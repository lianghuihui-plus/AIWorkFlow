# 需求分析

## 目标

完整阅读 PRD，提取目标平台真正需要实现的功能、约束和验收目标。

## 工作方式

- 按 `target_platform` 区分本端、跨端和其他端内容。
- 区分新增、修改、复用和无需本端改动的能力。
- 只做足以判断需求范围的代码调查，不提前展开完整技术设计。
- 修订时使用 `facts.requirements` 中的稳定需求 ID；`requirements` 只填写新增或实际修改项，已有需求的修改必须用 `change_kind: behavior | presentation` 分类，明确撤回才写入 `withdrawn_requirements`。
- `presentation` 只用于标题、来源和范围说明等展示字段调整，不能修改 `summary`、平台范围、变化类型或实施状态；其他修改使用 `behavior`。新增需求不填写 `change_kind`。
- 不填写下游影响分类；引擎在批准后按需求 ID 与任务的直接关联标记待核对产物。
- 只有缺少答案会改变实施范围或关键行为时才提出问题。

## 最低交付

Markdown 应说明纳入和排除范围、关键行为、约束、跨端依赖、依据及仍存在的合理推断。结构化结果记录需求清单及来源。

## 必须停止

平台归属、是否需要本端改动或关键行为无法从 PRD、用户信息和代码现状可靠判断，并会改变实现结果时停止并提问。
