# 代码实现

## 目标

让当前任务的全部验收标准在当前代码中真实成立。

## 工作方式

- 先检查现有代码已经满足哪些验收标准，只补齐缺口。
- 其他任务顺带实现的代码可以直接复用；不要追踪代码属于哪个任务。
- 允许零代码变化，但必须完成必要验证并为每项验收标准提供证据。
- `changed_files` 只作报告，不与 Git 状态比较，也不限制文件类型。
- 报告只负责当前任务，不推进其他任务状态。

## 最低交付

结果必须包含 `summary`、`acceptance_results`、`changed_files`、`validation` 和 `risks`。`acceptance_results` 必须逐项对应任务规格的 `acceptance_criteria`，每项都为 `passed` 并给出代码或行为证据；`validation` 至少记录一项实际验证。

## 必须停止

缺少业务决定或安全关键前提，无法保证验收标准正确落地时停止并提问。
