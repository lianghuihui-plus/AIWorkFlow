# 代码实现

## 要解决的问题

按照当前任务规格把生产代码落实到真实仓库，并根据代码事实处理规格未覆盖的局部问题，留下可审核的实现报告。

## 工作方式

- 先理解相关现有代码、项目约定、依赖任务结果和任务开始前已有差异。
- 按规格实现正常、异常和兼容行为，复用现有模式并控制修改范围。
- 规格与代码现实冲突时先判断影响：局部、可逆且不改变目标的选择由 Agent 自主完成并记录；改变需求、架构、公开行为或任务边界时停止并提出问题。
- 如实际实现偏离规格，报告规格要求、实际选择、原因和影响，不把偏离隐藏在文件清单中。
- 执行与风险相称的编译、静态检查或已有验证命令。

本阶段只修改生产代码、配置和资源，不新增或修改单元测试、测试夹具、Mock 或断言。执行已有测试可以作为回归验证，但不能在本阶段补写测试代码。

## 最低交付内容

报告必须覆盖实际修改、关键实现判断、与规格的差异、已执行验证、未解决问题和风险。结果清单登记本任务实际触碰的生产文件及验证摘要。

## 必须停止的情况

实现必须改变已批准需求、技术架构、公开兼容承诺或任务边界，或者可能覆盖无法归属的既有改动时，提交阻塞问题。能够由仓库事实支撑的局部实现选择不阻塞。
